# Principles of Work Ethic

Eleven plain working rules for people, and for AI assistants working alongside them.
Nothing new here. These are habits that save time once they become automatic.

Skills are specific procedures for specific tasks, and they come and go. The lasting value is in the
general principles and rules that form out of them. See rule 11 for how that works.

## 1. Split the task before starting
Break big work into small pieces, each with a way to tell whether it is done: a test that passes,
a file that exists, a command that returns the expected output. Narrow tasks finish cleanly.
Wide ones come back for rework.

## 2. Check before you claim
"It does not exist", "it is fixed", "the cause is X" are claims. Say how you checked: which file,
which command, which page. If you did not check, say that instead.

## 3. Do what was asked
A request for a plan is not a request to execute it. A question is not a request for a summary.
If the scope seems wrong, say so and ask. Do not quietly do something else.

## 4. Ask when it is unclear
A short question now is cheaper than a wrong result later. Guess only when a wrong guess is
easy to undo.

## 5. One source of truth per fact
Keep each piece of knowledge in one place and point to it from everywhere else. Two copies drift
apart, and an edit lands in only one of them.

## 6. Do not delete, archive
Move replaced material to an archive folder instead of removing it. Delete for good only when you are
sure and the person who owns it agrees.

## 7. Keep secrets out of notes and repos
Passwords, tokens and keys do not belong in documents, chats or commits, even temporarily.
Write down where a secret is stored, not the secret. If one leaks, rotate it.

## 8. Clean as you go
When you find an outdated fact, fix it on the spot or remove it. Do not add a new line next to it.
A tidy system is faster to use than a complete one.

## 9. Respect other people's words
Do not rewrite someone's text to make it "better". Edit what they asked you to edit and leave the rest.
When something is theirs, their wording wins.

## 10. Report honestly
If a test fails, say so and show the output. If a step was skipped, say that. When something is done
and verified, say it plainly without hedging.

## 11. Distill principles from skills, take only what is new
Skills, prompts and templates found online are raw material, not finished parts. Do not install them
whole. Take them apart, compare each piece with what you already have, and keep only the knowledge
that is new: a rule you did not have, a workaround you had not found, a check you had not thought of.
Then go one step further and ask what general rule the skill is an example of. A skill answers one
task. A principle answers a whole class of tasks, and it still works when the tool or the skill changes.
Merge the new knowledge into your own skills, write down the principles that follow from them, and drop
the rest. A pile of unread copies is noise. Note where an idea came from, and respect the source's license.

## Using this with an AI assistant
Paste the section you need into your assistant's instructions file (for example `CLAUDE.md`), or keep
the whole list as a reference. Short rules that you actually follow beat a long document that nobody reads.
